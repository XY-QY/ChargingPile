# 充电桩管理系统 ChargingPile

> 郑州大学校园电动车充电桩管理系统 —— Scrum 敏捷开发分组实验（Sprint 1 + Sprint 2 迭代交付）

一个面向校园四大宿舍区（柳园 / 荷园 / 菊园 / 松园）的在线充电桩管理平台：用户可查看充电桩分布与实时状态、按区域搜索、基于定位查看最近充电桩、在线开始/结束充电、钱包充值并支付电费；管理员可查看全量数据统计与分析。

## 迭代目标

### Sprint 1 迭代目标（2026-10-08 ~ 2026-10-12）
完成充电桩管理系统的核心业务闭环，交付可运行的 MVP：
1. **用户体系**：注册、登录、退出，HttpSession 会话管理 + 登录拦截器（未登录访问受保护页面自动跳转登录）；
2. **充电桩总览**：展示全部充电桩分布与使用状态，空闲/使用中清晰标识，使用中的桩显示剩余充电时长；
3. **区域查询**：柳园、荷园、菊园、松园四大区域分类筛选 + 关键词搜索；
4. **定位找桩**：打开网站自动获取浏览器定位，按 Haversine 距离优先展示最近的一批充电桩；
5. **开始充电**：选择充电桩与充电时长（分钟），开始前校验钱包余额（预估费用 ≤ 余额），余额不足提示充值；
6. **结束充电与计费**：按郑州市标准电价、每度电费计费，充电时长不满整数的按向上取整计算，自动从钱包扣款；
7. **钱包充值**：50 / 100 / 200 / 500 及自定义金额充值，充值后余额即时更新。

**Sprint 1 验收标准**：本地 localhost:8088 可完成"注册 → 登录 → 找桩 → 充电 → 计费 → 充值"全流程演示，数据库 ChargingPile 数据完整。

### Sprint 2 迭代目标（2026-10-12 ~ 2026-10-13）
在 Sprint 1 基础上完成增强功能与运营支撑，交付可对外演示的 1.0 版本：
1. **钱包流水**：充值、充电消费、退款全量流水记录，余额变动可追溯；
2. **充电记录查询**：用户查看全部历史充电订单（桩名称、时间、度数、费用、状态）；
3. **管理员统计与分析**：充电桩总数/空闲/使用中、用户数、订单数、累计收入、累计电量总览，四大区域收入明细，近 7 天收入趋势（ECharts 折线图）、区域分布（柱状图）；
4. **管理员明细**：用户列表、订单列表、流水列表全量查看；
5. **超时订单自动结算**：定时任务每分钟扫描，到达预计结束时间的订单自动结束并结算扣费，避免用户忘记结束造成桩位占用；
6. **公网发布**：通过 Cpolar 内网穿透创建云网站，所有用户均可登录使用。

**Sprint 2 验收标准**：公网地址可访问，管理员登录 admin/admin123 可查看全部统计与明细，超时订单自动结算生效。

## 计费规则（郑州市标准）

```
费用 = 度数(kWh) × 每度电价(元/度)
度数 = 计费时长(小时) × 桩功率(kW)
计费时长 = 实际充电时长 向上取整 到整数小时
```

- 示例：7kW 桩充电 1 小时 20 分 → 计费时长按 2 小时 → 度数 14 kWh → 费用 14 × 1.20 = 16.80 元
- 桩电价：慢充（7kW）1.20 元/度，快充（120kW）1.30 元/度
- 开始充电前余额预校验，不足则提示充值；结束充电或超时自动结算时扣款并写入钱包流水

## 快速开始

### 1. 启动数据库（Docker + OpenGauss）

```bash
# 已有 opengauss 容器，端口 5432，用户 opengauss，密码 Gauss@123
# 执行 init.sql 初始化建库建表与初始数据
```

### 2. 修改配置并启动后端

`src/main/resources/application.yml` 中配置数据源指向 OpenGauss `ChargingPile` 库，然后：

```bash
mvn clean package -DskipTests
java -jar target/ChargingPile-1.0.0.jar
```

### 3. 访问

- 本地：http://localhost:8088
- 公网：通过 Cpolar 隧道（示例 https://6ab3cb4c.r19.cpolar.top）转发到 localhost:8088
